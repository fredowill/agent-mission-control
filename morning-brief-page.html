💡 Key Findings from This Session f057–f059
f057 · principle
Update reference data before dispatching dependent agents
Stale data in = stale output out. Update campaigns.json before agents read it.
When an agent reads campaigns.json or any shared data file as context, that file must be accurate FIRST. Dispatching an agent to overhaul a page while its data source is stale means building on wrong foundations. Reference data accuracy is a pre-condition, not a follow-up task.
"If the campaigns page becomes a place that is used for reference then we can't send out agents to do something before we update the reference file."
f058 · principle
Orchestrators should not run sub-agents — dispatch to separate CLIs
Sub-agents are invisible. Write prompts, user dispatches in separate terminals.
v1.2 ran Campaign Architect and Skill Creator as sub-agents within its own session. Problems: agents invisible to Dashboard, orchestrator context bloated, user can't monitor progress, defeats coordinate-don't-build. Correct pattern: write PRD prompts, user dispatches in separate terminals.
"I don't think it's a good abstraction to have the orchestrator run subagents. Having separate CLIs makes more sense so you can preserve context for orchestrating."
f059 · principle
All text must use bold-lead pattern — no paragraph walls
Bold keyword first, concise description after. Debrief wins list = gold standard.
Debrief wins list is the gold standard: bold key text up front, concise description after, metrics color-coded, View links inline. Every text block in MC should follow this pattern. If text needs more than 2 sentences, break it into multiple bold-lead items.
"This type of stuff. Love this type of text, so easy to understand. You need to make all text like this. This should be a finding."
